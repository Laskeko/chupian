# 出片搭子 ChuPian — 需求文档

版本：v0.1（Phase 1 立项稿）
状态：待评审
日期：2026-11

---

## 一、我们要解决什么

两个真实痛点，都发生在按下快门前的 10 秒：

**痛点 1：机位焦虑。**
到了一个景，不知道有没有人拍过、人家是怎么构图的。现有解法是打开小红书手动搜同点位——关键词靠猜、结果靠翻、参考图和眼前实景对不上，全程还被同行的人催。

**痛点 2：拍人焦虑。**
不知道当前环境该拍近景、中景还是远景；不知道被拍的人喜欢什么、上次那么拍她为什么不满意。每次都是现拍现猜，快门三十张，能看的没一张。

**通用性声明**：本产品不锁定"拍对象"场景。被拍者可以是任何人——伴侣、闺蜜、孩子、父母、用户自己。个性化机制对所有被拍者一视同仁，每人一份偏好画像。

## 二、产品定位

**开源 AI 摄影搭子**。一句话：抬起手机，就知怎么拍。

三条产品原则：

1. **私有素材库是产品核心**。用户手机相册的收藏夹 = 机位索引 + 偏好画像来源。不爬数据、不建公共库、零合规负担。
2. **数据不出设备**。素材、画像、向量索引全部本地；云端 VLM 只接收一帧画面且可关闭。
3. **推荐要确定性的**。场景知识靠查表（内置知识卡库），LLM 只负责个性化组合，不负责编造事实。

## 三、用户与核心场景

**目标用户**：对照片有要求但不成体系的普通用户。典型画像：想给同行的人拍出好照片、自己也想被拍好看的人。

**验收基准场景**（Phase 1 效果承诺的锚点，见第七节）：

> 周末出游。打开 App，授权导入收藏夹里 50 张参考图，离线打标建库。走到一处湖边亭子前抬起手机：2 秒内提示"此点位命中 3 张参考图"，取景框叠加构图框和参考角度；点"怎么拍"，1~2 秒给出 3 个拍法（远景对称构图压水面 / 中景靠栏回眸 / 近景逆光发丝特写），每个附景别、站位、姿势要点；对方摆好姿势后骨架校验提示"下巴收一点"；拍完选"要/不要"。全程云端调用 ≤ 3 次。

## 四、功能需求

优先级：P0 = Phase 1 必须交付；P1 = 紧随其后；P2 = 后续。

### F1 素材库（P0）

- 通过系统相册（Photo Picker / SAF，只授权指定相册或用户选择目录）导入收藏夹图片，批量离线打标：景别（近/中/远）、构图、姿势、场景、光线。
- 端侧 CLIP embedding 建立向量索引（百张级规模，毫秒检索）。
- 读取 EXIF 定位（如有）作为点位 GPS 粗筛依据。
- **多画像**：为不同被拍者建独立偏好 profile（结构化 JSON），切换即用。

### F2 点位匹配（P0）

- 取景帧每 1~2 秒做一次 embedding 检索（非逐帧，控功耗）。
- 相似度超阈值即判定命中：取景框半透明叠加参考图 + 对应构图框线。
- 带定位的参考图先做 GPS 半径粗筛（默认 200m），降低误匹配。
- 命中后允许用户一键确认，同点位后续会话直接复用（粗召回 + 精确认的两段式）。

### F3 场景识别与拍法推荐（P0）

- 云端 VLM 分析一帧：识别环境类型与光线条件（日落逆光 / 阴天柔光 / 林间斑驳 / 夜景霓虹……）。
- 命中内置**场景知识卡**（确定性建议：拍法、景别选择、光线处理、避坑），再结合当前被拍者的偏好 profile，输出 2~4 个具体拍法。
- 一次场景只调用一次，结果本地缓存，场景变化才重新调用。
- VLM 可插拔：默认 GLM-4V-Flash（免费档），支持用户自填 key 切换豆包/Qwen-VL 等。
- DeepSeek 类纯文本模型不适配本链路（无视觉），不做支持。

### F4 取景叠加（P0）

- 构图辅助：三分线 / 中心对称 / 引导线，随推荐拍法切换。
- 人物站位圈：推荐拍法附带"人站这"的落位提示。
- 骨架参考线：ML Kit Pose Detection 实时检测，姿态与建议偏差大时给轻提示（"下巴收一点""左肩沉一点"）。
- 叠加层不遮挡取景主体，透明度可调。

### F5 偏好画像与反馈闭环（P1）

- 画像冷启动：导入时对该被拍者的好评样片打标，聚合出偏好（景别/构图/表情/道具偏好）。
- 现场反馈：成片"要/不要"轻量回流，加权更新 profile。
- 画像为纯本地 JSON：透明、可备份、可导出分享。

### F6 场景知识卡库（P1）

- 知识卡 = 一种场景的确定性拍法指南（初始库 20 张，见 scene-cards.md）。
- 作为开源内容资产，社区可提 PR 扩充——本项目的核心共建面。

### F7 纯离线模式（P1）

- 关闭云端调用：保留点位匹配、构图叠加、知识卡查表推荐，个性化组合降级为规则拼接。

## 五、非功能需求

| 项 | 要求 |
|---|---|
| 隐私 | 素材/画像/索引零上传；VLM 仅收一帧且可全局关闭；相册权限最小化（仅指定相册） |
| 打标性能 | 100 张导入打标建索引 < 2 分钟 |
| 匹配延迟 | 单次点位匹配（含 embedding）< 1s |
| 推荐延迟 | 场景拍法推荐端到端 1~2.5s |
| 叠加性能 | 取景叠加层稳定 30fps |
| 云成本 | 单次出片流程云调用 ≤ 3 次；免费模型默认 |
| 平台 | Phase 1 Android 原生（Kotlin + Jetpack Compose + CameraX + ML Kit Pose Detection + TFLite/MobileCLIP）；iOS 不做（核心成员无 iOS 设备），架构保持跨平台可能性（核心逻辑与数据格式平台无关） |

## 六、技术架构

```
┌──────────────────────── 手机端（隐私边界）────────────────────────┐
│                                                                  │
│  离线层                实时层                  交互层             │
│  · 收藏夹导入          · 取景帧 embedding        · 构图框叠加     │
│  · VLM 批量打标        · CLIP 向量检索 (<1s)     · 站位圈         │
│  · CLIP 索引构建       · ML Kit 骨架 30fps       · 骨架校验提示   │
│  · 偏好 profile 聚合                                             │
│  · 场景知识卡库（本地）                                            │
└───────────────────────────┬──────────────────────────────────────┘
                            │ 仅一帧（可关闭）
                    ┌───────▼─────────┐
                    │  云端 VLM（可插拔）│  GLM-4V-Flash（默认/免费）
                    └─────────────────┘  豆包视觉 / Qwen-VL（自填 key）
```

关键决策记录：

1. **不做模型训练**。个性化 = 结构化 profile + 上下文工程，效果稳、可解释、零训练成本。
2. **推荐分层**：知识卡查表给确定性建议，VLM 只做识别与个性化组合——避免 LLM 即兴编造摄影知识。
3. **匹配两段式**：CLIP 粗召回 + 用户一键确认，规避相似场景误匹配的工程深水区（局部特征精匹配留待后续）。

## 七、本期目标（Phase 1 / v0.1 效果承诺）

**达到什么效果**：第三节"验收基准场景"完整跑通。拆成验收指标：

| # | 验收项 | 达标线 |
|---|---|---|
| 1 | 收藏夹导入打标 | 100 张 < 2 分钟，字段完整率 > 90% |
| 2 | 点位匹配 | 主观 top1 准确率 > 80%，响应 < 1s，支持参考图叠加 |
| 3 | 场景拍法推荐 | 延迟 1~2.5s，输出含景别/构图/站位/姿势要素，单场景缓存 |
| 4 | 取景叠加 | 30fps 无掉帧，构图框 + 站位圈 + 骨架提示可用 |
| 5 | 多画像 | ≥ 2 个被拍者画像切换，推荐结果可区分 |
| 6 | 隐私 | 除可关闭的单帧 VLM 调用外零网络请求，材料可审计 |

**本期明确不做**（防止范围蔓延）：

- ❌ 模型训练 / 微调（任何形式）
- ❌ 公共机位社区、UGC 上传共享
- ❌ 后期修图（只管按下快门前）
- ❌ 应用商店上架（APK / GitHub Releases 直接分发，开源项目不上架）
- ❌ iOS（核心成员无 iOS 设备；核心逻辑与数据格式保持平台无关，为社区承接 iOS 留可能性）

## 九、风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 相似场景误匹配（隔壁亭子也命中） | 体验减分 | GPS 粗筛 + 一键确认两段式；深水区精匹配后置 |
| VLM 免费档限流/下线 | 推荐不可用 | 多 VLM 适配层 + 离线降级模式兜底 |
| 打标质量不稳（景别/姿势识别错误） | 偏好画像失真 | 打标结果允许手动纠错；置信度低的字段不进画像 |
| Android 各厂商相册/相片选取机制碎片化（Photo Picker 兼容性差异） | 导入体验打折 | 统一走系统 Photo Picker 兜底手动多选；目标 minSdk 26+ |
| 低端机端侧 embedding 性能不足（>1s） | 点位匹配变慢 | 量化 MobileCLIP / TFLite 模型；匹配频率自适应（1s→2s→3s 降档） |
